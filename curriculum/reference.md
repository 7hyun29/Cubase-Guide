**Cubase Pro 15 · Windows 학습 커리큘럼**

최초 작성: 2026-10-19 · 최신 개정: 2026-11-05 · 하루 총 약 60분 · 한국어 안내와 영문 메뉴 병기

2026-11-01 사용자 요청: 12월 말까지 Cubase 기본 기능 숙달을 최대한 마치고, 실제 음악 작업을 빠르게 진행할 수 있도록 학습 시간을 약 1시간으로 늘린다. 이 개정에서는 하루 총 60분으로 적용한다. 2026-10-20에 추가한 외부 플러그인의 설치 위치·인식·사용·관리 학습은 유지한다. 여기에서 정한 하루 60분과 12월 말 목표는 재시작 후에도 적용한다.

**2026-11-05 재시작 · 현재 진도는 공통 기초 01회차**

사용자가 Windows PC를 초기화하고 01회차부터 다시 진행하기로 했다. 첫 실습은 연습 전용 폴더에 빈 프로젝트를 만들고, 짧은 WAV를 가져와 현재 출력 장치에서 재생한 뒤, 저장한 프로젝트를 다시 열어 같은 소리를 확인하는 것이다. 예전 연습 파일 없이 새로 시작한다. 예시 결과 파일명은 `01_Project_Start.cpr`이다.

재시작 이후 완료 보고가 들어오면 그 회차를 기록한다. 일부만 확인되면 다음 수업에서 남은 동작을 이어간다. 01회차 완료 보고 후에 02회차 ‘화면과 Inspector’로 진행한다. 초기화 전 01~03회차 완료 및 04회차 부분 해결은 문서 끝에 과거 이력으로 보존한다. 현재 PC의 Cubase·플러그인 설치, 오디오 드라이버·포트, 사용자 지정키 상태는 새로 확인한다.

현재 우선 목표는 **2026-12-31까지 프로젝트 생성 → 녹음·MIDI/오디오 편집 → 기본 라우팅·오토메이션 → 내보내기·백업을 독립적으로 수행하고, 자주 쓰는 조작의 검색·망설임·재작업 시간을 줄이는 것**이다. 오케스트레이션 → 사운드 디자인 → 방송용 프로젝트 제작의 장기 순서는 유지한다. 목적별 응용 단계의 진입은 기초 평가 결과로 결정한다.

기존 12주 배분은 이전 초안이며, 현재 일정은 아래 11~12월 계획을 따른다. 기초 기능의 1차 실습 목표는 12월 6일, 반복 적용·보완·최종 검증 목표는 12월 31일이다. 날짜는 계획상의 목표이며 숙달을 보장하지 않는다. 완료 보고 없이 다음 회차를 자동 제공하거나, 달력 날짜만으로 진도를 올리지 않는다.

방송용 프로젝트는 마이크·건반·BGM의 입력, 처리, 모니터링, 출력을 관리하는 Cubase 템플릿을 뜻하는 것으로 잡았다. 방송 앱 연결은 실제 오디오 인터페이스와 드라이버, 사용 앱을 확인해 맞춘다. 아래 프로젝트와 음원 이름은 앞으로 만들 목표이며, 이 문서에 실제 Cubase 프로젝트 파일이 포함되어 있지는 않다.

**하루 60분의 기본 구성**

| 활동 | 시간 | 수행 내용 |
|---|---:|---|
| 이전 기능 재현 | 10분 | 정답을 보지 않고 이전 명령·작업을 실행하고 막힌 항목만 보충 |
| 핵심 설명·영상 | 10분 | 한국어 설명과 주제에 맞는 영상 일부 시청; 실제 영상 시청은 이 시간 안에서 최대 5~10분 |
| 오늘의 기능 실습 | 20분 | 오늘의 핵심 기능을 현재 연습 프로젝트에서 수행 |
| 실제 적용·시간 측정 | 15분 | 같은 기능을 다른 구간·소스 또는 실제 작업의 별도 복사본에 적용; 자료 없이 재현 |
| 저장·짧은 보고 | 5분 | 저장·필요한 재열기 확인, 완료 여부·소요 시간·막힌 점 기록 |

합계: 10 + 10 + 20 + 15 + 5 = 60분. 자료 없는 재현이 실제 적용 구간에 포함된다. 통합·평가일에는 설명·실습 시간을 줄여 30분 독립 평가와 결과 점검에 재배분한다. 한 세션에서 새 단축키는 최대 3~5개이며, 실제 사용자 지정키를 우선한다.

매주 새 학습 중심 5일 + 통합 적용 1일 + 복습·보충 1일을 기본으로 한다. 관련 기능을 같은 60분 안에서 연결해 학습할 수 있지만, 앞 항목 완료를 사용자 보고로 확인한 뒤 다음 항목을 제공한다. 확인 전에는 다음 항목을 학습한 것으로 처리하지 않고 현재 항목의 설명·복습·다른 소스 적용을 제공한다. 부족한 진도는 12월의 반복·보완 기간에 반영한다.

**2026년 11~12월 운영 계획**

재시작일인 11월 5일부터 12월 31일까지 양 끝 날짜를 포함하면 11월 26일분 + 12월 31일분 = 57일이다. 매일 실제로 60분을 학습할 경우 57 × 60분 = 3,420분 = 57시간이다. 기간별로는 1차 학습 32일 + 반복 적용 14일 + 최종 보완 11일 = 57일이다. 실제 공부한 시간은 완료 보고로 따로 기록한다.

11월 5일에는 01회차부터 재개한다. 02회차 이후에도 직전 회차의 새 완료 보고를 확인한다. 위 표의 뒤쪽 주간 주제는 목표이며, 그 기간까지 도달하지 않은 기초 항목은 순서대로 이어간다. 일정이 밀리면 12월의 반복·보완 기간을 활용한다.

01회차에는 짧은 WAV 하나와 소리를 들을 헤드셋 또는 스피커를 사용한다. 연습용 WAV를 새로 가져오면 이전 프로젝트나 외부 가상악기가 없어도 재생과 저장을 확인할 수 있다. 가상악기 실습에 도달하면 그때 현재 Windows PC에서 설치·인증이 확인된 제품을 선택한다. 설치가 필요한 경우 해당 항목은 확인 대기로 두고, 사용할 수 있는 내장 도구로 공통 조작을 먼저 익힌다.

**외부 플러그인 학습의 범위와 기준**

여기서 외부 플러그인은 Cubase에서 사용하는 다른 제조사의 소프트웨어 악기·이펙트를 뜻한다. 현재 Windows PC의 실제 설치 상태를 기준으로 학습한다. 과거에 다른 컴퓨터에서 사용한 제품이라는 이유만으로 이 PC에도 설치되어 있다고 가정하지 않는다. Kontakt·OPUS·Serum·Spectrasonics 제품을 사용할 때는 제품명·버전·설치 상태를 먼저 확인한다.

기존 42회차의 관련 과제에 아래 내용을 나눠 넣는다. 02회차는 관리창 위치 찾기까지만 진행하고, 03회차는 위치·형식 구분, 15회차는 가상악기 사용, 30~31회차는 효과 적용, 36·39회차는 파일 관리와 설정 재사용을 담당한다. 실제 설치나 오류 해결이 오래 걸리면 원인 확인을 별도 보충으로 관리하고, 가능한 공통 조작은 내장 도구로 진행한다. 다운로드 대기 시간을 독립 실습을 완료한 시간과 구분한다.

| 구분 | 확인할 위치·의미 | 학습할 내용 |
|---|---|---|
| VST3 플러그인 | Windows 64비트 공용 표준 경로 `C:\Program Files\Common Files\VST3`, 확장자 `.vst3` | 제조사 설치 프로그램으로 설치하고 실제 파일과 Cubase 인식 여부 확인 |
| VST2 플러그인 | 확장자 `.dll`, 경로는 제품·설치 선택에 따라 다름 | 실제 설치 폴더와 Cubase의 VST2 검색 경로 대조 |
| 독립 실행 프로그램 | Cubase 밖에서 실행하는 앱의 설치 위치 | 앱이 실행되는지와 Cubase용 플러그인이 설치됐는지를 각각 확인 |
| 샘플·라이브러리 | 악기에서 사용하는 콘텐츠 폴더 | 플러그인 경로와 따로 기록하고 제조사별 위치 지정·재연결 방법 학습 |

경로·콘텐츠 구분 근거: [Steinberg — VST plug-in locations on Windows](https://helpcenter.steinberg.de/hc/en-us/articles/115000177084-VST-plug-in-locations-on-Windows), [Native Instruments — Native Access 설치 위치 구분](https://support.native-instruments.com/support/solutions/articles/69000879242-native-access-changing-install-locations). 표의 공용 경로를 사용자의 실제 설치 경로로 단정하지 않는다.

Cubase Pro 15는 64비트 VST2·VST3 플러그인을 지원하며, Steinberg는 가능한 경우 VST3 사용을 권장한다. [공식 매뉴얼: Installing and Managing VST Plug-ins](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/installing_and_managing_plugins/installing_and_managing_plugins_plugin_manager_installing_vst_plugins_c.html)

설치·인식 확인은 다음 흐름으로 익힌다.

1. 사용할 제품 하나의 Windows용 64비트 VST 설치 여부와 제조사 설치·인증 상태를 확인한다. 새 설치가 필요할 때만 해당 제품의 공식 설치 절차를 따른다.
2. `Studio > VST Plug-in Manager`에서 악기는 `VST Instruments`, 효과는 `VST Effects` 목록에서 검색한다. 선택한 제품의 `Show VST Plug-in Information`도 확인한다.
3. 새 설치 후 인식이 필요하면 `Scan for new and blocked plug-ins` 또는 Cubase 재시작을 사용한다. 목록에 없다고 바로 파일을 이동하지 않는다.
4. VST2 제품이라면 `Enable VST 2 Plug-ins` 상태를 확인하고 `VST 2 Plug-in Path Settings > Add Path`에서 실제 설치 폴더를 연결한다. 이 경로 추가 기능은 VST2용이며 VST3 경로 설정으로 설명하지 않는다.
5. 목록의 필터·활성 Collection과 `Blocklist`를 확인한다. Blocklist는 안정성 문제 때문에 로드되지 않은 플러그인을 보여 주므로, 호환성·업데이트·실제 오류를 확인한 뒤 해당 제품의 조치를 정한다.

조작 근거: [VST Plug-in Manager Window](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/installing_and_managing_plugins/installing_and_managing_plugins_plugin_manager_window_r.html), [Toolbar: 검색·스캔·VST2 활성화·Collection](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/installing_and_managing_plugins/installing_and_managing_plugins_vst_plug_in_manager_toolbar_r.html), [VST 2 Plug-in Path Settings](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/installing_and_managing_plugins/installing_and_managing_plugins_vst_plug_in_manager_settings_r.html).

| 사용 과제 | 시작 조작 | 확인할 결과 |
|---|---|---|
| 외부 가상악기 한 개 | 트랙 목록의 `Add Track > Instrument`에서 설치된 악기를 선택하고 `Add Track` | 제품 안에서 패치·프리셋을 불러온 뒤 MIDI 입력 또는 파트 재생으로 소리 확인 |
| 외부 이펙트 한 개 | 오디오 트랙 선택 > `Edit Channel Settings > Inserts`의 빈 슬롯에서 효과 선택 | 파라미터 하나를 바꿔 듣고 우회 전후를 비교 |
| 공용 리버브 | 31회차의 FX 채널·Send 실습에 보유 제품 적용 | 두 트랙의 전송량을 각각 조절하고 경로 설명 |
| 설정 재사용 | 사용한 음색·효과 상태로 프로젝트 저장·재열기 | 같은 제품과 설정이 다시 로드되는지 확인하고 39회차에서 프리셋·템플릿으로 확장 |

불러오기 근거: [Creating Instrument Tracks](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/vst_instruments/vst_insruments_creating_instrument_tracks_t.html), [Adding Insert Effects](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/audio_effects/audio_effects_insert_effects_adding_t.html). 제품 내부의 패치·프리셋 메뉴는 실제 제품과 버전에 맞춰 별도로 확인한다.

오류가 생기면 먼저 어느 단계가 실패했는지 구분한다. 아래는 수업에서 사용할 진단 순서이며 사용자의 원인을 미리 확정한 것이 아니다.

| 증상 | 우선 확인할 내용 |
|---|---|
| 관리창에 제품이 없음 | VST 설치 여부·64비트 형식·검색/필터·스캔 결과, VST2이면 활성화와 검색 경로 |

| 악기·패치는 열리나 소리가 없음 | MIDI 입력/파트, 악기 내부 출력, 트랙 출력과 헤드셋까지의 경로를 순서대로 확인 |
| 다시 열 때 플러그인 누락 | 저장한 제품명·형식·버전과 현재 인식 상태 대조 |

위치를 바꿀 때는 플러그인 파일과 콘텐츠를 구분하고 제조사가 정한 절차를 사용한다. 플러그인은 여러 파일·설정에 의존할 수 있고, 샘플 이동 방법은 제품별로 다르다. [Steinberg — Relocating plug-ins / Content](https://helpcenter.steinberg.de/hc/en-us/articles/115000177084-VST-plug-in-locations-on-Windows)

완료 목표는 (1) 설치 위치와 샘플 위치를 구분해서 설명하기, (2) 악기 한 개와 효과 한 개를 올바른 위치에 불러오기, (3) 소리·파라미터 변화를 확인하기, (4) 프로젝트 재열기 후 설정을 확인하기다. 각 항목은 관련 회차에서 하나씩 완료한다. 새 기능을 한 수업에 몰아넣지 않는다. 각 수업의 유튜브 자료도 해당 조작에 맞는 직접 링크를 확인해 제공한다.

|---|---|---|---|---|---|

**기초 과정 통과 기준**

다음 작업을 영상 없이 30분 안에 수행하는 것을 목표로 한다. 첫 시도 시간이 넘으면 실패한 기능을 분리해 보충하고 다시 수행한다.

1. 새 프로젝트를 지정한 폴더에 저장한다.
2. 가상악기 트랙 2개와 오디오 트랙 1개로 8마디 재생 구간을 만든다.
3. MIDI 음높이·길이·시작 위치를 수정하고, 이벤트 복제·분할·Undo를 수행한다.
4. 로케이터를 선택 구간에 맞추고 반복 재생한다.
5. 공용 리버브와 볼륨 오토메이션을 한 번씩 적용한다.
6. WAV를 내보내고 저장한 프로젝트를 다시 열어 재생한다.

같은 기준을 서로 다른 두 세션에서 충족하면 기초 평가를 통과한 것으로 본다. 두 번째에는 다른 MIDI·WAV 소스를 사용해 적용을 확인한다. 목표 시한은 2026-12-31이며, 기본 조작의 정확성·독립 수행·저장 결과를 먼저 확인한다. 편곡의 예술적 완성도는 응용 과정에서 별도로 평가한다.

종합 평가만으로 모든 세부 기능을 완료 처리하지 않는다. 01~42의 핵심 과제별로 완료·보완 필요·미확인을 구분하고, 실제 입력·녹음 장치가 확인되지 않은 항목도 남긴다. 외부 플러그인 불러오기와 재열기, 오디오 녹음·편집, 파일 참조·백업·복원은 관련 회차의 실제 결과로 확인한다.

**실제 작업 속도를 높이는 반복 실습**

매주 통합 적용에서는 ① 구간 찾기·편집·복구, ② MIDI 녹음·수정, ③ 트랙·효과·라우팅 구성, ④ 저장·내보내기 중 해당 주에 배운 작업 묶음을 시간을 재며 수행한다. 첫 정상 완료 시간을 개인 기준으로 기록한다. 이후 같은 길이·트랙 수·난이도의 과제에서 자료를 찾아본 횟수와 수정이 필요했던 실수도 함께 비교한다. 사전 측정 없이 속도 향상률을 약속하지 않는다.

막힌 원인을 한 번에 하나씩 보충한다. 예: 단축키를 잊음, 선택 대상이 다름, 다른 창에 포커스가 있음, 출력 경로를 잘못 고름. 자주 쓰는 명령부터 사용자 지정키를 정리하고, 기본 라우팅과 트랙 설정은 39회차 템플릿 실습에 반영한다. 매크로는 40회차에서 개별 명령을 이해한 뒤 필요할 때 적용한다.

12월 반복 적용은 실제 카피·편곡 작업의 짧은 구간을 별도 복사본으로 사용한다. 새 프로젝트 준비 → 8~16마디 녹음·편집 → 트랙 간 복사·배열 → 기본 밸런스·오토메이션 → WAV 내보내기·재열기를 이어서 수행한다. 평가용 과제는 8마디·악기 2트랙·오디오 1트랙으로 유지해 비교한다. 보고된 시간이 줄어도 오류·누락이 늘면 숙달 향상으로 판단하지 않는다.

아래는 기존 응용 범위다. 12월의 우선순위는 기본 조작의 독립 수행과 작업 속도이며, 응용 진입 여부는 실제 완료 상태에 맞춘다.

오케스트레이션 단계에서는 음역·보이싱·악기 역할을 짧게 연결하되, 주된 훈련 대상은 Cubase에서 해당 의도를 구현하는 조작이다. CC1·CC11이 모든 패치에서 같은 기능을 맡는다고 가정하지 않는다. 주법 전환용 노트와 실제 연주용 노트를 구분하고, 패치 매뉴얼과 반응을 확인한다.

사운드 디자인은 Cubase 안에서의 제어·편집·재사용에 초점을 둔다. 내장 신스로 기본 동작을 익힌 뒤 보유 중인 Serum 등에 적용할 수 있다. 특정 프리셋 이름이나 설정값을 확인 없이 고정하지 않는다.

방송 연결 단계에서는 인터페이스 모델, 실제 사용 ASIO 드라이버, Windows 버전, 방송 앱, 출력·헤드폰 사용 방식, 루프백 지원 여부를 확인한다. Control Room은 모니터링 학습에 사용하며, 이것만으로 방송 앱에 소리가 전달된다고 가정하지 않는다. Cubase 프로젝트와 함께 장치·포트·방송 앱 설정도 기록한다. OBS를 쓸 경우 같은 장치를 전역 오디오와 별도 소스로 중복 캡처하는지 확인한다.

추가 환경 기록: 사용자가 적은 `splice sound / sample`, `VST3`는 그대로 보관하되 정확한 제품명·버전·본체 폴더·샘플 경로와 개별 플러그인 동작은 미확인이다. VST3라는 형식 보고를 실제 폴더 주소 확인으로 간주하지 않는다. Splice Sounds Plugin을 단순히 샘플 서비스라고 부정하거나 Bridge로 추정하지 않는다. 샘플 위치는 해당 앱·제품의 공식 경로 안내로 확인한다. OPUS 설치 오류 해결 여부도 별도 미확인 상태다. 이 자료와 당시 01~03회차 완료 보고는 초기화 전의 기록이다.

이 문서는 학습 계획과 사용자 보고를 기록한다. 실제 Cubase 프로젝트 파일을 직접 검사했다는 뜻은 아니다. 예약 수업은 기존 오전 10시(Asia/Seoul)를 유지하며, 사용자가 읽고 실습할 시각을 강제하지 않는다.
